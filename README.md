# STEPI 랜덤 게임

과학기술정책연구원(STEPI) 레크리에이션 게임 모음. 프레임워크·빌드 없이 HTML/CSS/JS만으로 만들어 **GitHub Pages에서 바로 동작**합니다.

- 허브: `https://max32767-commits.github.io/stepi-quiz/`
- 진행자는 노트북을 큰 화면에 띄워 진행하고, 참가자는 휴대폰으로 접속합니다.
- 단발성 게임이라 결과를 저장하지 않습니다. 여러 명이 동시에 접속하는 게임만 Supabase(무료)를 씁니다.

## 게임

| 🧠 꼬맨틀 `games/kkomentle` | 여럿이 휴대폰 | Supabase | 단어 의미 유사도 추측 협동 게임 |

공통 기능 💬 소통 채팅방 `games/chat` — 게임이 아니라 허브 상단 「💬 채팅방」(참가자 폰) · 히어로의 「채팅 큰 화면」(프로젝터)으로 들어간다. 메시지·이모지가 큰 화면 말풍선으로, 진행자 PIN으로 일시정지·가리기·비우기, `?room=` 으로 방 분리.

새 게임 추가: `games/<id>/index.html` 폴더를 만들고 `games.js` 배열에 한 줄 추가. 각 게임 페이지 끝에 `<script src="../../shared/home.js"></script>`를 넣으면 "랜덤 게임 홈" 버튼이 붙습니다.

## 배포 — Render (원하는 주소로)

1. https://render.com 가입 → GitHub 연결
2. **New → Blueprint** → `stepi-quiz` 저장소 선택 → `render.yaml` 이 읽혀 정적 사이트가 만들어진다 (이름 `stepi-games` → `https://stepi-games.onrender.com`, 이름은 대시보드에서 변경 가능)
3. 이후 `main` 에 푸시할 때마다 자동 배포. 커스텀 도메인은 Settings → Custom Domains.
- 무료 플랜(월 100GB 전송) 으로 충분. 서버 코드가 없으므로 Supabase 설정·PIN·게임 동작은 GitHub Pages 와 동일.
- 꼬맨틀 진행자 화면의 "큰 화면 열기", 각 게임의 QR 은 현재 주소 기준으로 만들어지므로 Render 주소로 접속하면 QR 도 Render 주소가 된다.

## 배포 (GitHub Pages)

1. 저장소 Settings → Pages → Build and deployment: **Deploy from a branch**, Branch `main` / `(root)` → Save
2. 1~2분 뒤 위 주소로 접속

## 멀티플레이 설정 (OX 퀴즈·꼬맨틀) — 설정 완료

Supabase 프로젝트 `stepi-quiz`에 연결돼 있고(`shared/supabase-config.js`), 스키마와 꼬맨틀 단어 벡터(68,550단어 · 정답 후보 3,260개)까지 올라가 있어 바로 동작합니다.

다른 프로젝트로 옮길 때:
1. SQL Editor에 `supabase/schema.sql` 전체를 붙여넣고 Run
2. Project Settings → API의 **Project URL**과 **publishable(anon)** 키를 `shared/supabase-config.js`에 입력 후 커밋
   - 공개돼도 되는 키입니다. **service_role 키는 절대 넣지 마세요.**
3. (꼬맨틀만) 단어 벡터 업로드 — `supabase/upload_words.py` 상단 설명대로 한 번 실행

> 레크리에이션용이라 로그인 없이 누구나 쓰도록 DB 정책을 열어 두었습니다. 행사 후에는 Supabase 프로젝트를 Pause 해 두세요.

## 진행자 PIN (OX 퀴즈·꼬맨틀 공통)

- 진행자 화면(`games/ox/host.html`, `games/kkomentle/host.html`)은 **진행자 PIN**을 넣어야 열리고, 라운드 열기·방 운영 같은 동작은 서버(RPC)에서도 PIN을 검사합니다. URL만 안다고 정답을 보거나 게임을 조작할 수 없습니다.
- PIN 설정·변경: **`admin/`** (슈퍼관리자 페이지). 처음 한 번 슈퍼관리자 PIN과 진행자 PIN을 정하고, 이후엔 슈퍼관리자 PIN으로 언제든 바꿉니다. 배포 직후 반드시 먼저 설정하세요.

## 꼬맨틀 사용법

- **행사 10분 전에 진행자 화면을 미리 열어 두세요.** 열려 있는 동안 4분마다 단어 벡터 캐시를 데워 두어(warm_up) 첫 추측이 느려지는 일을 막습니다. DB 인스턴스가 작아(캐시 224MB) 오래 쉬면 첫 검색이 수 초 걸릴 수 있습니다.

- 큰 화면: `games/kkomentle/screen.html` — 참가자 QR과 모두의 추측이 실시간으로 올라오는 프로젝터용 화면(정답 없음, PIN 불필요). 진행자 화면(정답 입력)은 노트북에만 두고, 큰 화면만 프로젝터에 띄운다.
- 진행자 화면에는 이번 라운드 정답이 가려진 채 표시되고(「보기」로 확인, RPC host_answer·PIN 필요), 새 라운드를 열면 메시지에 정답이 함께 나온다.
- 진행자: `games/kkomentle/host.html` (PIN) → 화면의 QR을 참가자에게 보여주고, **정답 단어를 넣어 새 라운드**를 엽니다 (사전 12.8만 단어 중에서만, 앞글자 찾기 지원). 비우면 랜덤 정답. 새 라운드를 열면 진행 중 라운드는 종료되고 그 정답이 공개됩니다.
- 참가자: QR 또는 `games/kkomentle/play.html` 에서 이름 입력 후 단어 추측. 모두 같은 라운드에 참여합니다.
- 사전에 없는 단어를 정답으로 쓰려면: fastText에 있는 단어는 `supabase/make_word_sql.py` 로 SQL을 만들어 SQL Editor에서 실행, 없는 신조어는 관련 단어 벡터의 평균으로 합성(예: 부캉이).

## 스피드 퀴즈 사용법

- 진행자: `games/ox/host.html` (PIN) → 문제 입력(한 줄에 `문제|정답`, 복수 정답은 `/`, OX 문제는 `|O`/`|X`) → 제한시간 설정 → **방 만들기** → QR/코드로 참가자 입장 → **게임 시작**
- 문제마다 제한시간이 돌고, 참가자는 폰으로 답을 제출합니다(틀리면 재시도 가능). 채점은 서버에서 하며 정답 키는 클라이언트에 내려가지 않습니다.
- 점수: 정답 50점 + 속도 보너스(남은 시간 비례, 최대 50) + 순위 보너스(1등 30·2등 20·3등 10). 시간이 끝나면 자동 공개, 모든 문제 후 총점 순위 발표.

## 실시간 로또 사용법

- 진행자: `games/lotto/host.html` (PIN) → 1·2·3등 인원 설정 → **방 만들기** → 참가자가 QR로 들어와 번호 6개 선택 → **번호 마감** → **번호 뽑기** 6번(서버 난수) → **결과 확정**
- 순위: 맞힌 개수 많은 순, 같으면 먼저 제출한 순. 설정한 인원만큼 1·2·3등이 채워집니다(0개 맞혀도 순위로 채움).

## 반응속도 대결 사용법

- 진행자: `games/reaction/host.html` (PIN) → 라운드 수·페이크 비율 설정 → **방 만들기** → 참가자가 QR로 입장(이름 입력, 서버 시계 자동 동기화) → **라운드 시작**
- 시작 후 3~8초 뒤(서버가 정한 시각) 큰 화면과 모든 폰이 **동시에** 바뀝니다. 초록 GO → 빨리 누르기, 빨강 STOP → 참기.
- 점수: 반응시간 순위 10·9·8…(최소 1점) / STOP을 참으면 +5, 누르면 −5 / 신호 전 또는 100ms 미만은 부정출발 −3 / GO를 안 누르면 0.
- 반응시간은 폰에서 로컬로 재서 서버로 보내고, 서버는 신호 시각과 비교해 신호 전 제출을 거릅니다. 결과는 라운드마다 공개, 마지막에 총점 순위와 특별상(최고 반응속도·최다 낚임).

## 닮은꼴 찾기 메모

- `games/lookalike/models/` : InsightFace buffalo_sc 팩(SCRFD-500m 검출 2.5MB + ArcFace MobileFaceNet w600k_mbf 13.6MB), `games/lookalike/ort/` : onnxruntime-web 1.19.2 런타임(11MB). 전부 정적 파일이라 GitHub Pages에서 그대로 동작하고 사진은 브라우저 밖으로 나가지 않는다.
- 점수 = 두 얼굴 임베딩의 코사인 유사도를 `face.js`의 CURVE 표로 0~100에 펴서 표시. 서로 다른 사람끼리는 대체로 -0.1~0.3에 몰리므로 표를 조정해 체감 점수 폭을 바꿀 수 있다.
- 부위별 설명(`parts.js`)은 MediaPipe Face Mesh(`games/lookalike/mp/`, 11MB) 468점 랜드마크로 얼굴형·눈매·코·입매·눈썹의 기하 특징을 재서 비교한다. 각 부위 점수(0~100)와 "특히 닮은 부위" 문장, 가장 다른 부위 한 줄을 만든다. 기준값·허용 오차는 parts.js의 PARTS 표.
- 여러 명이 찍힌 사진은 가장 큰 얼굴을 쓴다. 옆모습·마스크·너무 작은 얼굴은 "얼굴 못 찾음"으로 표시되니 정면 사진으로 바꿀 것.

## 공통점 찾기 사용법

- 진행자: `games/common/host.html` (PIN) → 질문 목록(`질문 | 왼쪽 답 | 오른쪽 답`, 기본 17문항 내장) → **방 만들기** → QR 입장 → **첫 질문 시작** → 참가자가 폰에서 고르면 **결과 보기**(같은 답끼리 명단·비율) → **다음 질문** … → 마지막에 **가장 많이 겹친 짝 TOP 5**
- 참가자 폰: 답 마감 후 자기 편 인원·이름이 보이고, 끝나면 "나와 가장 잘 맞는 사람 TOP 5"(일치 수·%)가 나온다. 점수 없음.
- 테이블 cm_rooms / cm_players / cm_answers, RPC cm_create_room(pin, questions) / cm_join / cm_answer / cm_set_phase / cm_tally / cm_matches / cm_top_pairs

## 눈치 게임 · 인간 스톱워치 메모

- 눈치: `nz_press` 가 서버 시각(clock_timestamp)으로 기록, `nz_end_round` 가 앞뒤 사람과 window_ms(기본 150) 안이면 collide, 전원 외쳤으면 마지막 last, 안 외치면 silent. 생존 +10. 진행자 화면은 전원 외치면 0.6초 뒤 자동 마감, 제한 시간(기본 30초) 지나도 자동 마감.
- 스톱워치: 폰이 로컬로 잰 경과(ms)를 `sw_submit` 으로 보내고, 서버는 라운드 시작 후 실제 지난 시간+1.5초보다 긴 기록을 거른다. 오차 순 10·9·8…(최소 1), 미제출 0. random 모드는 라운드마다 3.00~10.00초.
